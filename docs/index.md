# healthchecksio Provider

Manages checks in one healthchecks.io project with the Management API v3. Each project has its own API keys. For more than one project, use one provider block for each project, with an `alias`.

The provider supports each endpoint of the Management API v3:

| API endpoint | Provider |
|---|---|
| Create, get, update and delete a check | Resource `healthchecksio_check` |
| List checks | Data source `healthchecksio_checks`, list resource `healthchecksio_check` |
| Get a check | Data source `healthchecksio_check` |
| Pause and resume a check | Actions `healthchecksio_pause` and `healthchecksio_resume` |
| List pings, get a ping body | Data sources `healthchecksio_pings` and `healthchecksio_ping_body` |
| List flips | Data source `healthchecksio_flips` |
| List integrations | Data source `healthchecksio_channels` |
| List badges | Data source `healthchecksio_badges` |
| Status | Data source `healthchecksio_status` |

The API cannot make or change projects, integrations or team members. Use the dashboard
for them.

## Why this provider

I previously used an existing provider, `kristofferahl/healthchecksio`, before building
this. However, at the time it used API v1, exposed the UUID ping credential
in plans and logs, and had no data source for checks, pings, or flips, no pause and resume
actions, and no identity or keyword filters. I made this provider to fix some of those
gaps for myself, and later open sourced and published it in case anyone else might
benefit from it. The guide "Move from kristofferahl/healthchecksio" gives the
procedure to move your checks.

## The id of a check

The `id` of `healthchecksio_check` is the unique_key of the check (40 hex digits), not its
UUID. The UUID is the ping credential, and Terraform shows the `id` in each plan. The
`uuid` and `ping_url` attributes are sensitive. The state contains them. Thus, keep the
state in a private backend.

|---|---|---|

## Example Usage

```terraform
terraform {
  required_providers {
    healthchecksio = {
      source  = "jshvn/healthchecksio"
      version = "~> 1.0"
    }
  }
}

# The provider reads the API key from HEALTHCHECKSIO_API_KEY. Do not write a key in a file.
provider "healthchecksio" {}

# Each project has its own API keys. For a second project, use a second provider block
# with an alias.
provider "healthchecksio" {
  alias   = "backups"
  api_key = var.backups_api_key
}

variable "backups_api_key" {
  type      = string
  sensitive = true
}
```

## Schema

### Optional

- `api_key` (String, Sensitive) The API key of the project. Get it on the **Project Settings** page. A read-only key is sufficient for the check, checks, badges and flips data sources. The resource and the actions need a read-write key. If you do not set it, the provider uses `HEALTHCHECKSIO_API_KEY`.
- `api_url` (String) The API root. The path must end in `/api/v3/`. For a self-hosted server, use `<SITE_ROOT>/api/v3/`. If you do not set it, the provider uses `HEALTHCHECKSIO_API_URL`, then `https://healthchecks.io/api/v3/`.
